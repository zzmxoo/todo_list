# 桌面待办 · 项目交接与上下文摘要

> 更新：2026-11-23 · 最新 tag：`0.0.8`
> 用途：后续会话 / 协作者先读本文件，快速恢复产品背景、设计规范、技术约束和测试约定。

## 1. 项目定位

Windows 桌面待办小组件。无边框、深色玻璃、窗口置顶、可贴边隐藏；主界面是待办列表，日历模式为「左待办 + 右月历」单页布局，天气和每日一句作为辅助信息。

- 技术栈：Tauri v2 + WebView2 + Rust；前端为原生 HTML/CSS/JS，**无 Node 构建、无框架、无打包器**。
- 数据只存本机：`%APPDATA%\com.desktoptodo.widget\data.json`。
- 发布版：`cargo build --release` 后运行 `src-tauri\target\release\desktop-todo.exe`，前端资源编译进 exe。
- 仓库当前没有配置远程，提交和 tag 都在本地。

## 2. 原始需求与演进记录

## 3. 功能规范

### 3.1 待办

- 字段：`id`、`text`、`created`、`due`、`start`、`done`、`done_at`、`pinned`。
- 操作：新增、置顶、双击编辑、删除、标记完成、设置/清除截止时间。
- 排序：置顶优先；未完成在前；同组保持稳定。
- 截止状态：超时、30 分钟内即将到期、普通、已完成；对应不同状态点。
- 已完成项**不显示**在列表中；UI 不支持取消完成；`sortTodos` 仍把完成项排在后面以兼容数据。
- 空状态文案区分“暂无待办”和“全部完成”。
- 新增输入框在后台重绘（跨天 tick 等）时保留草稿和焦点。

### 3.2 日历

- 单页布局：左侧待办列 300px，右侧月历 393px，窗口内容宽约 717–718px，高约 392–416px（含边距）。
- 月历按周渲染，周一至周日固定 7 列，通常 5–6 行。
- 事项从创建日持续到截止日；色条跨周切片，跨月只保留本月部分。
- 同一周重叠事项逐行下排，**最多同时显示 3 行**；滚轮在该周内滚动，顶部/底部溢出用 `+n` 表示。
- `+n` 只出现在该行末尾（周日列），数字取该周各天隐藏条数的最大值，避免每个日期格重复。
- 双击日期格或色条打开添加弹窗；色条覆盖格子上方时也能命中（日期格之间 2px 间隙取最近格）。
- 右键日期格立即显示农历、节气、天气、每日一句；鼠标悬停 3 秒显示，离开 1.2 秒消失。
- 节气当天显示节气名与专属背景。
- 法定节假日：缓存于 `settings.holidays`，每个假期日都显示名称和底色；多天假期每天都有标签。
- 日历模式打开设置时，窗口最多补足到 `SETTINGS_W + 2*MARGIN + CAL_TODO_W + GAP ≈ 740px`，面板不遮挡待办。

### 3.3 设置

- 右侧浮动面板：宽 404px，`position: absolute; right: 12px; top: 12px`；标题栏可拖动窗口。
- 分页（左侧图标）：系统配置、界面配置、天气配置、AI 接入、关于。AI 页按 WorkBuddy / DeepSeek Harness / 豆包 展开显示接入方式，`command` 使用 `desktop-todo.exe` 通用写法（不写死本机路径）。再次点击标题栏设置图标可以关闭设置面板。
- 系统配置顺序固定：
  1. 极简模式
  2. 日历模式
  3. 窗口置顶
  4. 不在任务栏显示
  5. 允许开机启动
  6. 导出最近 30 天
- 极简模式与日历模式互斥：打开日历会关闭极简，反之亦然。
- 设置打开期间切换模式不立即改主界面；关闭设置后由 `doLayout()` 一次性应用。
- 普通模式打开设置按 `SETTINGS_W + GAP + MARGIN` 加宽；日历模式只补足必要宽度。
- 关于页当前只显示版本号（来自 `tauri.app.getVersion()`），预留检查升级入口。

### 3.4 界面与外观

- 默认透明度 0.9；滑杆按 gamma 2.2 换算成 sRGB alpha（`opacityFromTransparency`）。
- 字体：微软雅黑（默认）、雅黑、宋体、楷体、仿宋、黑体、等线；字体颜色支持预设色板与自定义色。
- 背景图：`--card-image` 填充卡片内部，支持 fill / stretch / tile；外层 `#bgImage` 永久隐藏。
- 玻璃色、字体色、透明度均通过 CSS 变量实时生效。
- 极简模式：每条待办单行；打开天气时待办列表撑满，添加行贴卡片底部。

### 3.5 天气

- 默认数据源：Open-Meteo 地理编码 + 预报，无需 key。
- 自定义链接识别：和风天气、彩云天气、uapis.cn；请求由 Rust `fetch_json` 代发，绕开 CORS。
- 天气卡片宽 250px，展示实时、今日温度区间、7 日预报；日历模式在日期格显示天气图标。
- 展开/收起窗口为即时扩缩，**不要加窗口尺寸动画**（历史尝试导致明显卡顿）。
- 网络失败时显示占位，不影响待办。
- 自定义链接（含 key/token）只保存在本机 `data.json`。

### 3.6 窗口吸附与边缘隐藏

- 默认窗口 400×360，最小 300×200；不可缩放、不可最大化/最小化，无边框、透明、无阴影，默认置顶。
- 位置保存在 `settings.x/y`，启动时恢复并夹在可见屏幕内。

关键常量（`ui/app.js`）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `SNAP_DIST` | 20px | 靠边吸附距离 |
| `EDGE_SLIVER` | 36px | 收起后露出的窄条厚度 |
| `EDGE_REVEAL_MS` | 800ms | 悬停唤出延迟 |
| `EDGE_LEAVE_MS` | 700ms | 移开后收起延迟 |
| `EDGE_HIDE_ANIM_MS` / `EDGE_SHOW_ANIM_MS` | 378ms | 收起/弹出动画 |
| `TOP_DWELL_MS` | 2000ms | 拖到上边缘停留多久触发上边收起 |
| `TRAY_HIDE_MS` | 5000ms | 托盘唤出后自动缩回 |
| `MAX_BARS` | 3 | 日历每周最多显示行数 |

行为：

- 窗口拖动结束后 20px 内吸附到屏幕边缘。
- 左右侧边：按待办行左侧原点/五角星到窗口边缘的距离做左右对称阈值，窗口越过该距离后才收起；底边仍按移出超过 1/3（可见比例 < 2/3）收起。
- 拖到上边缘并按住 2 秒，向上收起。
- 收起后窗口只留 36px 窄条：左右窄条 24px 宽、垂直居中 50% 高；上下窄条 50% 宽、24px 高；四角 12px 圆角。
- 鼠标移入窄边 0.8 秒唤出；移开 0.7 秒收起。
- 点击窄边立即唤出，不等待悬停计时；点击后 700ms 内吞掉 click/dblclick，避免误触。
- 刚收起时鼠标仍在窄边上不会自动弹出；需要先移开一次（armed）再回来。
- 收起状态下拖动窗口离开边缘即退出隐藏。
- 唤出动画使用 Rust `animate_window` 逐帧移动；Rust 发出 `edge-anim-start` 后前端启动内容缩放/淡入，避免窗口与内容不同步。
- 动画期间忽略 `onMoved` 的重复收起判断，避免抖动/回弹。

### 3.7 托盘、任务栏与开机启动

- 默认托盘图标隐藏、任务栏按钮显示。
- 打开“不在任务栏显示”：`set_skip_taskbar(true)`，并把托盘图标显示出来（进入系统托盘溢出区）。
- 托盘菜单：显示主界面、退出程序；左键单击也显示主界面。
- 显示时如果窗口处于边缘收起状态，会立即唤出，并在 5 秒后自动缩回；鼠标停在窗口上则每秒顺延。
- 开机启动写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `DesktopTodo`，数据为带引号的当前 exe 路径（路径含空格也能启动）。
- 开关交互必须先同步反馈，再异步写注册表；写入失败回滚开关。
- 程序单实例运行：第二个进程直接退出，避免两个实例交替全量写 `data.json`。

### 3.8 导出

- 范围：最近 30 天内完成的事项，按完成时间排序。
- 格式：每行 `创建时间，完成时间，内容`，时间格式 `yyyy-MM-dd HH:mm`，CRLF 换行。
- 通过原生保存对话框导出 `.txt`；没有记录时按钮提示“暂无记录”。

### 3.9 AI 接入

- 外部 AI 工具（DeepSeek Harness、WorkBuddy、豆包等）通过 MCP stdio 或 CLI 写入待办。
- MCP：`desktop-todo.exe --mcp`，提供 `add_todo`、`add_todos`、`list_todos`。
- CLI：`desktop-todo.exe --add "..." [--due] [--start] [--duration] [--provider] [--source] [--pinned]`。
- 注册：`desktop-todo.exe --install-mcp workbuddy|dsh|generic [--exe <path>]`；WorkBuddy 写入本地插件市场（仍需用户点一次安装），DSH 生成配置片段，generic 输出 JSON。
- 会议支持：`start` + `duration_minutes`（或 `time`/`due` + `duration`），服务端自动算结束时间；列表显示 `10:30–11:30`，日历按区间绘制。
- 写入走 `%APPDATA%\com.desktoptodo.widget\ai-inbox\<id>.json` 收件箱；桌面端每秒 drain，按 id 去重后合并进 `data.json`。
- 桌面端未运行时收件箱保留，下次启动合并；不监听端口、不联网。
- 列表给 AI 待办显示来源标签；未知 provider 按通用字段解析。
- 字段适配集中在 `src-tauri/src/ai/providers.rs` 的 `PROVIDERS`，新增客户端只加一条配置。
- 详细配置见 [`docs/AI_INTEGRATION.md`](AI_INTEGRATION.md)。

## 4. 技术与设计约束（不要轻易打破）

1. **无 Node 构建**：前端是直接加载的 HTML/CSS/JS；模块用 UMD 风格挂到 `window`。不要引入 React/Vue/Vite/Webpack/Vitest。
2. **无在线依赖的业务数据**：名言内置；节假日可联网获取但必须缓存并可离线降级；天气失败不阻塞主功能。
3. **数据本地化**：无账号、无云同步、无遥测；图片复制到应用数据目录。
4. **Rust 只做薄胶水**：文件读写、原生对话框、HTTP 转发、窗口动画、托盘、注册表。业务规则不要塞进 Rust。
5. **写操作统一出口**：前端待办写操作走 `commitTodos()`（保存 + 重绘 + 布局），避免局部刷新不一致。
6. **纯函数优先**：规则放 `ui/core.js` / `ui/domain/*` / `ui/weather.js`，可单测；DOM 代码留在 `app.js`。
7. **测试跟着风险走**：JS 规则用单测，DOM/窗口/托盘用真实 WebView 集成，Rust 只测可抽出的纯函数；不要为了覆盖率搭重型 E2E。
8. **修改必须带回归用例**：见 `tests/TESTING.md` 与 `tests/REGRESSION.md`。

## 8. 关键设计决策与原因

- **设置改右侧浮动面板**：不遮挡待办，且在日历模式下不会把窗口撑大；打开设置时先退出边缘隐藏。
- **模式切换延迟到设置关闭**：避免设置面板打开时日历被隐藏、布局跳变。
- **背景图放卡片内部**：外层画布保持透明，玻璃卡片仍然可见；`#bgImage` 不再渲染。
- **已完成单向**：用户明确要求完成后不可取消；数据保留用于日历色条、导出和统计。
- **天气不做尺寸动画**：尝试过平滑过渡，实际比即时扩缩更卡，已回退。
- **边缘动画 Rust 驱动**：每帧 IPC 在系统繁忙时抖动；改为 Rust 侧定时移动，1ms 定时器精度，前端只做内容缩放。
- **窄条不做窗口宽度缩放**：改为固定窄条 + 两端圆角，避免缩放导致末端方形和回弹。
- **`+n` 只贴周日列**：原来每个日期格都标，视觉噪音大；数字取每天隐藏数的最大值，避免累加错误。
- **日历色条最多 3 行**：保证月历高度稳定；溢出通过每周独立滚轮查看。
- **开机启动乐观 UI**：`reg.exe` 写入约 0.3–0.7 秒，先同步翻转开关，后台写入，失败回滚。
- **2px 间隙命中**：色条中心可能落在日期格之间，`cellAtPoint` 取最近格，保证双击色条可靠。

## 9. 已知限制与风险

- 天气、节假日依赖网络；uapis 可能 429，集成测试会跳过；节假日首次查看某年需要联网，失败则无标签。
- 开机启动记录的是 exe 绝对路径；移动/重命名程序后需要重新开关一次。
- 托盘图标是否进入溢出区、任务栏按钮是否消失，只能在真实 Windows 桌面确认。
- 窗口动画在低性能/远程桌面环境可能仍有轻微掉帧，测试只约束位置、时长、无回弹和单层结构。
- `data.json` 是唯一数据源；没有自动备份机制。测试脚本会备份/恢复。
- 无安装包、无自动更新、无远程仓库。
