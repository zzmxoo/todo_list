# 回归测试集

本文件是回归用例的**清单**：每个已修复的问题、每条必须长期保持的行为，都要能在这里找到对应的自动化用例。
`tests/integration-page.js` 中的用例名直接带 `[REG-xx]` 编号，方便从失败项反查历史问题。

## 运行

```powershell
powershell -ExecutionPolicy Bypass -File tests\regression.ps1
```

一条命令会：构建带 CDP 端口的测试版（`src-tauri/target-test/`，不污染发布版）→ 跑 Rust 纯函数单测 → 备份 `data.json` → 启动测试版 → 跑领域/核心单元测试 → 校验名言库数据 → 跑 44 条 UI 集成回归 → 恢复数据并重新启动发布版。
只想跑 UI 层可加 `-SkipUnits -SkipRust`；只跳过 Rust 可加 `-SkipRust`。集成脚本本身是 `tests/integration-page.js`。分层原则与“该写单元还是集成”的判断见 [`tests/TESTING.md`](TESTING.md)。

## 维护规则（每次修复 bug 必须做）

1. **先补用例**：在 `tests/integration-page.js` 加一条 `[REG-新编号]`，或在对应 `unit-*.js` 加单元用例；用例要在**修复前**能复现失败。
2. **再改代码**：修完后同一条用例必须通过。
3. **登记清单**：在本文件表格补一行：问题、修复提交、用例名/文件、自动化方式。
4. **全量回归**：提交前跑 `tests\regression.ps1`，不允许带着失败用例提交。
5. 编号只增不改；删除旧行为时保留用例并改成断言“该行为已不存在”，不要直接删掉历史用例。

## 无法完全自动化的部分（人工抽查）

- 收起 / 弹出动画的“观感”是否顿挫，自动化只能约束时长、位置、无回弹和单层结构。
- 托盘图标是否真的进入系统托盘溢出区、任务栏按钮是否消失，需要人工看任务栏。
- 开机启动在重启后是否真的拉起程序，需要在 Windows 登录后确认。
- 背景图选择对话框（原生文件选择器）无法在 CDP 中操作，自动化只校验 CSS 填充链路。
